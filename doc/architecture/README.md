# facilities Architecture

**facilities** is the lowest-level Fermi package. It has no Fermi or
third-party dependencies (apart from Python for its SWIG binding). It holds:

1. **`commonUtilities`**: the one place that maps a package name to its
   installed data, XML and par-file directories, and that sets the
   `<PKG>DATAPATH` / `<PKG>XMLPATH` / `CALDB` / `TIMING_DIR` environment
   variables. Nearly every package finds its files through it.
2. **`Util`**: static string helpers (environment-variable expansion,
   string↔number conversion, tokenizing, trimming).
3. A few legacy GLAST-era classes (`Timestamp`, `Scheduler`, `Observer`,
   `Adapter`, …), some still used, many not.

The Doxygen mainpage (`src/mainpage.h`) is three sentences long and says
`commonUtilities` is "needed for SCons builds". That is out of date: under
CMake it is still the data-path mechanism. `doc/release.notes` stops in 2015.

## Purpose and scope

**Does:**
- Resolve per-package install locations (`getDataPath`, `getXmlPath`,
  `getPfilesPath`, `getPackagePath`) from environment variables. The rule
  used depends on compile-time macros; CMake always selects the `HEADAS`
  rules (see [Path resolution](#path-resolution-the-important-part)).
- Set environment variables that XML files and other code refer to as
  `$(LIKELIHOODXMLPATH)`, `$(OBSERVATIONSIMDATAPATH)` and so on
  (`setupEnvironment`).
- Expand `$(VAR)` / `${VAR}` references in strings (`Util::expandEnvVar`).
- Convert strings to numbers with error checking (`Util::stringToDouble`,
  `stringToInt`, `stringToUnsigned`, `stringToUll`), tokenize, trim, basename.
- Expose `commonUtilities` to Python (`py_facilities` SWIG module).

**Does not:**
- Know anything about FITS, astronomy or the LAT.
- Check that the paths it returns exist. Every getter only concatenates
  strings.
- Read par files. That is `ape`/`hoops`/`st_app`. `getPfilesPath` only names
  the system pfiles directory.

## Position in the system

| Direction | Package | Why |
|-----------|---------|-----|
| Depends on | — | The C++ library links nothing. It includes `config.h` from `${CMAKE_BINARY_DIR}` (generated by the top-level `CMakeLists.txt`) for the `PACKAGES` list. |
| Depends on | Python 3 (external) | Only the `py_facilities` SWIG module links `Python3::Python`. |
| Used by (library code) | `Likelihood`, `irfs`, `celestialSources`, `dataSubselector`, `evtbin`, `fitsGen`, `flux`, `astro`, `st_facilities`, `st_app`, `xmlBase`, `SolarSystemTools`, `map_tools`, `observationSim`, `rspgen`, `timeSystem`, `orbitSim`, `healpix` | Mostly `commonUtilities.h` (getDataPath/getXmlPath/joinPath) and `Util.h` (expandEnvVar, string conversion). `astro` uses `Scheduler.h`/`Observer.h` (in `astro/GPS.h`); `observationSim` (`obsSim`) uses `Timestamp.h` (so does fitsGen's `makeFT2a`, which CMake does not build). |
| Used by (tests only) | `tip`, `optimizers`, `burstFit`, `catalogAccess` | `getDataPath` to locate test data; `catalogAccess` also includes the Windows-only `AssertDialogOverride.h`. |
| Used by (Python) | `sane` | `from facilities import py_facilities` in `GtApp.py`, `menu.py`, `pfilesPath.py`, only to call `getEnvironment`. |

Many packages reach `facilities` without listing it, because `tip`
(`PUBLIC facilities`) and `xmlBase` (`PUBLIC facilities`) pass it on. Of
the packages above, only `astro`, `fitsGen`, `flux`, `celestialSources`,
`st_app`, `SolarSystemTools`, `tip` and `xmlBase` name it in
`target_link_libraries`. `skymaps` (not built) also includes it.

Two wrappers sit on top of `commonUtilities` and are what most newer code
calls:
- `st_facilities::Environment` (in `st_facilities`): a singleton whose
  constructor calls `setupEnvironment()` once, then forwards `dataPath`,
  `xmlPath`, `packagePath` and `getEnv`.
- `st_app`'s standard `main` (`st_app/src/ballistic_main.cxx`) calls
  `setupEnvironment()` before any `gt*` tool runs.

## Key abstractions

| Type | Header | Role |
|------|--------|------|
| `commonUtilities` | `facilities/commonUtilities.h` | All-static class: path lookup, `getEnvironment`/`setEnvironment`, `joinPath`, `setupEnvironment`. |
| `Util` | `facilities/Util.h` | All-static string helpers. Throws `Untranslatable` (unknown env var) and `WrongType` (bad number). |
| `Timestamp`, `BadTimeInput` | `facilities/Timestamp.h` | UTC calendar time, 1970–2037, from string `"yyyy-mm-dd hh:mm:ss"`, Julian date or Unix seconds. Leap-second aware `getString(true)`. |
| `Scheduler`, `ScheduledEvent`, `GPStime` | `facilities/Scheduler.h`, `ScheduledEvent.h` | Singleton time-ordered event queue. Used by `astro::GPS` to read the simulation clock. |
| `Observer`, `Subject`, `ObserverAdapter` | `facilities/Observer.h` | Classic observer pattern; base of `astro::GPS`. |
| `XGetopt` | `facilities/XGetopt.h` | `getopt` for Windows. Compiled on all platforms; no callers. |
| `AssertDialogOverride` | `facilities/AssertDialogOverride.h` | Windows-only CRT assertion hook (header-only); guarded by `#ifdef WIN32` in its users. |

Header-only files with **no users** anywhere in `src/` (candidates for
removal): `Adapter.h`, `Commissioner.h`, `Converter.h`, `FIFO.h`,
`SimpleEvent.h`, `Utility.h`, `binarystream.h`, `bitmanip.h`,
`bpkt_streams.h`, `error.h`, `filemap.h`, `environmentCallback.h`, and
`Clock.h` (`src/Clock.cxx` is an empty one-line file).

## Data flow and control flow

### Path resolution (the important part)

`commonUtilities.cxx` has three implementations of each getter, chosen by
preprocessor macros: `SCons` (old SCons builds), `HEADAS` (HEASoft-style
installs), or neither (CMT-era `<PKG>ROOT` variables). The CMake build
compiles facilities with `HEADAS` and `ScienceTools` defined
(`CMakeLists.txt`: `target_compile_definitions(facilities PRIVATE HEADAS ScienceTools)`),
so **only the HEADAS branch is live**. In that branch the root for every
package is the same: `$FERMI_INST_DIR`.

| Call | Returns (CMake/HEADAS build) | Matching CMake install dir |
|------|------------------------------|----------------------------|
| `getPackageRoot(pkg)` (private) | `$FERMI_INST_DIR`, or `""` if unset | `share/fermitools` |
| `getDataPath(pkg)` | `$FERMI_INST_DIR/refdata/fermi/<pkg>` | `FERMI_INSTALL_REFDATADIR/<pkg>` |
| `getXmlPath(pkg)` | `$FERMI_INST_DIR/xml/fermi/<pkg>` | `FERMI_INSTALL_XMLDIR/<pkg>` |
| `getPfilesPath(pkg)` | `$FERMI_INST_DIR/syspfiles` (same for every package) | `FERMI_INSTALL_PFILESDIR` |
| `getPackagePath(pkg)` | `$FERMI_INST_DIR/<pkg>` (no such directory is installed) | — |
| `getJobOptionsPath(pkg)` | `$FERMI_INST_DIR/src`, or `""` | — (GlastRelease relic) |

The conda activation script (`recipe/activate.sh` in ScienceTools) sets
`FERMI_INST_DIR=$CONDA_PREFIX/share/fermitools`. **Note:** it is
`$CONDA_PREFIX/share/fermitools`, not `$CONDA_PREFIX`. So for an installed
package, `getDataPath("Likelihood")` is
`$CONDA_PREFIX/share/fermitools/refdata/fermi/Likelihood`, which is where
each package's `install(DIRECTORY data/ DESTINATION ${FERMI_INSTALL_REFDATADIR}/<pkg>)`
puts its `data/`.

Data is always read from the **install tree**, never the source tree. A test
run against a build directory finds its data only after `make install` (or
an equivalent install into the prefix `FERMI_INST_DIR` points at).

### setupEnvironment()

Under HEADAS + ScienceTools it does, in order:

1. For every name in `PACKAGES` (the space-separated `FERMI_COMPONENTS`
   list, baked into `config.h` at configure time), sets
   `<PKG>XMLPATH = getXmlPath(pkg)` and `<PKG>DATAPATH = getDataPath(pkg)`,
   with the name upper-cased (`LIKELIHOODXMLPATH`, `OBSERVATIONSIMDATAPATH`, …).
   A trailing `-NN-NN-NN` version suffix would be stripped (SCons relic).
2. Sets `TIMING_DIR = $FERMI_INST_DIR/refData`.
3. Sets `CALDB = getDataPath("caldb")` = `$FERMI_INST_DIR/refdata/fermi/caldb`,
   and `CALDBCONFIG`/`CALDBALIAS` beneath it.

Every `setEnvironment` call here uses `overwrite=false`: **a variable that
is already set is left alone.** In a normal conda environment the
activation script has already set `TIMING_DIR`, `CALDB`, `CALDBCONFIG` and
`CALDBALIAS` to the correct values, so steps 2–3 do nothing. See the
gotchas for what happens without activation.

These variables are then used by `Util::expandEnvVar` on strings from XML
and par files, e.g. `$(LIKELIHOODXMLPATH)/...` in Likelihood and
`$(XMLBASEXMLPATH)` in xmlBase.

Callers of `setupEnvironment()`: `st_app`'s `main` (all `gt*` tools),
`st_facilities::Environment` (first use), `irfLoader::Registrar`,
`fitsGen::EventClassifier`, `facilities.py` (on Python import), and most
test mains.

### Python

```
from facilities import py_facilities      # sane does this
  └─ python/facilities.py  (installed to site-packages/fermitools/)
       ├─ import py_facilities             # SWIG proxy, built into the build dir and installed next to it
       └─ py_facilities.commonUtilities.setupEnvironment()   # side effect on import
```

`site-packages/fermitools` and `$PREFIX/lib` are on `sys.path` through
`fermitools.pth`, written by the top-level `CMakeLists.txt`. The compiled
`_py_facilities` module is installed into `lib/`.

## Public interfaces

### C++ API

```cpp
#include "facilities/commonUtilities.h"
#include "facilities/Util.h"

using facilities::commonUtilities;
std::string f = commonUtilities::joinPath(
    commonUtilities::getDataPath("mypkg"), "table.fits");

std::string s("$(LIKELIHOODXMLPATH)/models.xml");
facilities::Util::expandEnvVar(&s);       // throws facilities::Untranslatable if unset
double x = facilities::Util::stringToDouble("1.5e3");  // throws facilities::WrongType
```

In new code, prefer `st_facilities::Environment::dataPath(pkg)`. It ensures
`setupEnvironment()` has been called. The package itself does not depend on
that call: `getDataPath` reads `FERMI_INST_DIR` directly.

### Applications

None. The three test programs (below) are installed to `bin/`.

### Python

`py_facilities` (SWIG, `src/py_facilities.i`) wraps the whole of
`commonUtilities`. Use it as
`py_facilities.commonUtilities.getDataPath("pkg")`. `python/facilities.py`
re-exports it and calls `setupEnvironment()` at import time.
`src/py_facilities.in` is an unused near-duplicate of the `.i` file.

### Environment variables

The activation-set variables (`FERMI_INST_DIR`, `CALDB*`, `TIMING_DIR`, …)
are described under "Runtime environment" in ScienceTools'
`docs/architecture/README.md`. What facilities itself does with the
environment (live HEADAS branch only):

| Variable | Read or set by | Effect |
|----------|----------------|--------|
| `FERMI_INST_DIR` | read by `getPackageRoot` (`commonUtilities.cxx`) | Root of every path getter. Unset gives `""` and paths like `/refdata/fermi/<pkg>`. |
| `<PKG>XMLPATH`, `<PKG>DATAPATH` | set by `setupEnvironment()` if unset | One pair per `FERMI_COMPONENTS` entry, for `$(VAR)` references in XML and par files. |
| `TIMING_DIR`, `CALDB`, `CALDBCONFIG`, `CALDBALIAS` | set by `setupEnvironment()` if unset | Fallbacks only; activation normally sets them first (see [setupEnvironment()](#setupenvironment)). |
| any `VAR` | read by `Util::expandEnvVar` (`Util.cxx`) and `commonUtilities::getEnvironment` | `$(VAR)`/`${VAR}` expansion; throws `facilities::Untranslatable` if unset. |

The `<PKG>ROOT` scan of `environ` in `setupEnvironment()` belongs to the
non-HEADAS branch and is not compiled.

### File formats

None read or written. The SCons branch read `$INST_DIR/data/supersede.pkgList`,
but it is not compiled under CMake.

## Build and test

- **CMake targets:** `facilities` (shared library, compiled with
  `HEADAS ScienceTools`, plus `__APPLE__` on macOS); `py_facilities`
  (SWIG Python module, `-bundle -flat_namespace` on macOS). Headers are
  installed to `include/fermitools/facilities`, `python/facilities.py` and
  the generated `py_facilities.py` to `site-packages/fermitools`. There is no
  `data/`, `xml/` or `pfiles/` directory.
- **Tests:** `test_env`, `test_time`, `test_Util` (`src/test/`). They are
  built and installed to `bin/`, but **not registered with CTest**. All
  three are in the default run of the project harness
  `recipe/tests/ST-unit-test` (see "Testing" in ScienceTools'
  `docs/architecture/README.md`), which checks only their exit status; no
  output is compared and no facilities reference data exists anywhere.
  `test_env` returns the error count as its exit status. `test_time` always
  returns 0, and `test_Util` returns 1 only if one valid
  `stringToDouble` conversion throws, so those two otherwise fail only if
  they crash.
  - `test_env` checks `setEnvironment` overwrite rules and that
    `FACILITIESXMLPATH` matches `getXmlPath("facilities")` after
    `setupEnvironment()`. Its `getDataPath` emptiness check cannot fail
    under HEADAS (see gotchas).
  - `test_Util` expands `${GLAST_EXT}/xerces` and
    `$(FACILITIESROOT)/$(SRC)`. These are CMT/SCons-era variables, so in a
    normal environment it just prints "Untranslatable" messages.
  - No test data and no scratch files.
- **Legacy files:** `SConscript`, `facilitiesLib.py`, `.cvsignore`,
  `doc/index.html` (GLAST-era overview).
- **CI:** `azure-pipelines.yml` uses the shared `fermi-lat/ci` templates.

## Invariants and gotchas

**Path lookup**
- Under CMake, every getter ignores `<PKG>ROOT`, `INST_DIR` and
  `BASE_DIR`. Only `FERMI_INST_DIR` matters. The `SCons` and non-HEADAS
  branches in `commonUtilities.cxx` are dead code in this build, but they
  make the file hard to read; check `#ifdef HEADAS` first.
- **If `FERMI_INST_DIR` is unset, the getters do not return `""`.**
  `getDataPath`, `getXmlPath`, `getPfilesPath` and `getPackagePath` join
  onto an empty root and return paths such as `/refdata/fermi/Likelihood`
  (absolute, from `/`). Checks like `if (path == "")` in clients (e.g.
  `fitsGen::EventClassifier::pythonPath`, `test_env`) can never fire, and
  the real failure is a later "file not found" on a strange path. Only
  `getJobOptionsPath` still returns `""`.
- For the same reason, `setupEnvironment()`'s "CALDB environment variable
  not set properly" `runtime_error` can never be thrown under HEADAS.
- `getPfilesPath(pkg)` returns the same directory for all packages.
  `getPackagePath(pkg)` returns `$FERMI_INST_DIR/<pkg>`, which the CMake
  install does not create. `fitsGen::EventClassifier` builds a Python path
  from it (`$FERMI_INST_DIR/fitsGen/python`) (from reading the code; not
  checked at runtime).
- The paths name **installed** locations. Running tests from a build tree
  without installing finds no data, or stale data from an earlier install.

**setupEnvironment defaults that are wrong without activation**

These are masked in a conda environment because activation sets the
variables first and `setupEnvironment` never overwrites (from reading the
code and `recipe/activate.sh`; not checked at runtime):
- `CALDB` default is `$FERMI_INST_DIR/refdata/fermi/caldb`, but
  `irfs/caldb` installs to `share/fermitools/data/caldb`
  (`FERMI_INSTALL_DATADIR`). Activation sets `CALDB=$FERMI_DIR/data/caldb`.
- `TIMING_DIR` default is `$FERMI_INST_DIR/refData` (capital `D`, a
  directory that is not installed). Activation sets
  `.../refdata/fermi/jplephem`.
- Only names in `FERMI_COMPONENTS` get `<PKG>DATAPATH`/`XMLPATH`.
  Sub-libraries are not covered: `GENERICSOURCESDATAPATH` (used 21 times in
  celestialSources XML) is set only by `activate.sh`, and
  `GRBTEMPLATEDATAPATH` is not set by anything found in the repo.
- `PACKAGES` is fixed at configure time. Adding a package to
  `FERMI_COMPONENTS` needs a re-configure before its `<PKG>XMLPATH` exists.
- `fermitools-fhelp` produces `FERMITOOLS-FHELPXMLPATH`. The hyphen makes it
  unusable from a shell, but it is harmless.

**Util string helpers** (from reading `src/Util.cxx`; not checked at runtime)
- `expandEnvVar` replaces `envEnd + clLen` characters starting at
  `envStart`. That length is correct only when the variable starts at
  position 0, or is the last thing in the string. For `"a/$(X)/bc"`, the
  text after the variable is eaten. It also looks for the closing
  delimiter from the start of the string, not after the opening one. The
  usual `$(VAR)/file` form works.
- `expandEnvVar` throws `facilities::Untranslatable` for an unset variable.
  Partial expansions made before the throw stay in the string.
- `trimTrailing` (and so `trim`) on an empty or all-blank string indexes
  before the start of the string (`unsigned last = size - 1` underflows).
  `basename("")` dereferences `end() - 1` of an empty vector.
- `Util::itoa`/`utoa` return a pointer to a static buffer (not
  thread-safe). Use the `outStr` argument instead.
- `stringToDouble("3.")` is accepted, but any other trailing text throws.
  `stringToInt` rejects trailing text, including `"3.0"`.

**Timestamp**
- Valid only for 1970–2037; the constructors throw `BadTimeInput` outside
  that range.
- `getString(true)`'s leap-second table (`Timestamp::getAdjustment`) stops
  at 2015-07-01. It is **missing the 2016-12-31 leap second**, so it is off
  by one second for dates from 2017 on. No current caller uses it: the
  only built user, `obsSim` (observationSim), calls `getJulian()`, and
  fitsGen's `makeFT2a` (the other includer) is not built by CMake.
- Converts with `mktime` minus a timezone offset computed once at static
  initialization for 1970-01-01, not with `timegm`.

**Python**
- Importing `facilities` (the Python module) calls `setupEnvironment()`
  as a side effect, which changes `os.environ` of the process.
- `sane/python/menu.py` calls `py_facilities.commonUtilities_getEnvironment`,
  the old flattened static-method name. Newer SWIG versions (4.1+) do not
  generate it by default (inferred from SWIG release notes; not checked
  against the SWIG version used by the build).

## Extension points

- **New package that needs data, XML or par files:** do not add anything to
  facilities. Install `data/` to `${FERMI_INSTALL_REFDATADIR}/<pkg>` and
  `xml/` to `${FERMI_INSTALL_XMLDIR}/<pkg>`, add the package to
  `FERMI_COMPONENTS`, and look files up with
  `st_facilities::Environment::dataPath("<pkg>")` (or
  `commonUtilities::getDataPath`). `$(<PKG>XMLPATH)` and
  `$(<PKG>DATAPATH)` then work in XML strings passed through
  `Util::expandEnvVar`.
- **New environment variable set for all tools:** add it to
  `setupEnvironment()` inside the `HEADAS`/`ScienceTools` branch, and to
  `recipe/activate.*` in ScienceTools if shell users need it as well.
- **New string helper:** add a static method to `Util`. Keep facilities free
  of Fermi and third-party dependencies; astronomy-aware helpers belong in
  `astro` or `st_facilities`.

A change to `commonUtilities.h` or `Util.h` rebuilds almost the whole tree.
